# 広島 電子黒板・資材管理アプリ（GitHub Pages で一元管理）

センターの「電子黒板」「資材管理アプリ」と同じ仕組みを、広島拠点向けに小規模化して作ったもの。
広島は人数が少ないため、配置図・舟数モニターは無し。代わりに生産者記録と、進捗シートの
自動反映を試すための「テスト機能」を持つ。

**★今の段階の一番大事なルール**：発注書スプレッドシート（【広島】発注書2026年度）には
**一切書き込みません**（読み取り専用）。電子黒板から入力した数字は、専用に新規作成した
別スプレッドシート「【広島】電子黒板データ」にだけ保存されます。しばらく試してみて、
発注書の「進捗」シートの数字と食い違いが無いか確認できたら、次の段階として本番の
「進捗」シートへ書き込む機能を追加します（今回はまだ実装していません）。

## 中身

- `index.html` … 電子黒板（本日進捗タブ／生産者タブ）
- `shizai.html` … 資材管理アプリ（センターと同じ仕組み。手袋のシフト連動機能のみ広島には無いため省略）
- `gas/広島連携.gs` … バックエンド（Google Apps Script）のバックアップ。GAS本体はApps Scriptエディタ側で
  編集・再デプロイする（GitHub Pagesでは動かない）

## 使っているスプレッドシート

| 用途 | スプレッドシート | このアプリからの扱い |
|---|---|---|
| 発注書・進捗の現在値を見るだけ | 【広島】発注書2026年度 | **読み取り専用**（絶対に書き込まない） |
| 生産者記録・進捗テスト入力・資材データ等の保存先 | 【広島】電子黒板データ（新規作成） | 読み書き両方（このアプリの全ての保存先） |

## セットアップ手順（初回のみ）

### 1. Google Apps Script をデプロイする

1. 上のリンクで「【広島】電子黒板データ」を開く → メニュー「拡張機能」→「Apps Script」
2. エディタが開いたら、中身を全部消して `gas/広島連携.gs` の内容を丸ごと貼り付ける
3. 保存 → 上部の「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 実行するユーザー：自分
   - アクセスできるユーザー：**全員**（社内共有のURLとして使うため）
4. デプロイすると「ウェブアプリのURL」が発行される（`https://script.google.com/macros/s/.../exec`）。
   このURLを控える
5. エディタで `testDebug` 関数を選んで▶実行 → 初回は権限の承認画面が出るので許可する
   → 実行ログ（表示 → ログ）で、発注書スプレッドシートのシート名一覧・列見出しの検出結果が
   正しそうか確認する（ズレていたら `CFG.ORDER_MAIN_SHEET` / `CFG.ORDER_PROGRESS_SHEET` の
   シート名や `CFG.PROGRESS_KEYWORDS` を実際の表記に合わせて直す → 保存 → 「デプロイの管理」から
   新バージョンとして再デプロイ）

### 2. HTML側にGASのURLを設定する

- `index.html` の `const GAS_URL = '...'` の行に、手順1で控えたウェブアプリのURLを貼る
- `shizai.html` は開いた後、画面内の「設定」からGASのURLを入力する（`GAS_URL_DEFAULT` は空にしてあるので、
  最初の1回だけ入力すればブラウザに記憶される）

### 3. GitHub Pages で公開する

1. `git add -A && git commit -m "初回：広島電子黒板/資材アプリを配置"`
2. GitHubに新規リポジトリを作成してpush
3. リポジトリの Settings → Pages で公開（ブランチ・フォルダを指定）
4. 発行されたURL（`https://<アカウント>.github.io/<リポジトリ名>/`）を各PCでブックマークする

## 直し方（更新フロー）

1. `index.html` / `shizai.html` / `gas/広島連携.gs` を編集
2. GASを直した場合は、Apps Scriptエディタ側でも同じ内容を貼り直し、新バージョンとして再デプロイする
   （GitHubにpushしただけではGAS本体には反映されない）
3. `git add -A && git commit -m "説明" && git push`
4. 各PCは電子黒板を再読込（F5）するだけで最新になる

## 動作確認のしかた（デプロイ後）

- ブラウザで `<GASのウェブアプリURL>?type=debug` を直接開く（JSON文字列がそのまま表示される）
  → `orderSheetNames` に「発注書」「進捗」が入っているか、`main.labels` / `progress.labels` に
  それらしい列見出しが並んでいるかを確認する
- `<GASのウェブアプリURL>?type=progress` … 進捗シートの今日の値
- `<GASのウェブアプリURL>?type=funes` … 発注書シートの「収穫舟数」に相当する今日の値
  （2件以上ヒットしたら要注意。発注書に似た表が複数ある可能性がある）

## ⚠ このリポジトリに入れてはいけないもの

Excel（発注書・棚卸等）など**個人情報・社内データは絶対に置かない**（公開されるため）。
front-end の HTML と GAS のコードだけを置く。`.gitignore` で `*.xlsx` 等は除外済み。
